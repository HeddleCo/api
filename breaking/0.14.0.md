# 0.14.0 retired RPC removal

This intentionally breaking pre-1.0 revision removes five retired Weft RPCs
from the wire contract:

- `RegistryService/GetCurrentUserNamespace`, superseded by
  `RegistryService/GetCurrentUserSpool`.
- `RegistryService/CreateNamespace` and `RegistryService/CreateRepository`,
  superseded by `RegistryService/CreateSpool`.
- `IdentityService/RecordSubscription`, superseded by the Polar webhook relay.
- `IdentityService/MintBiscuit`; clients mint biscuits locally and Weft verifies
  device keys.

Weft is the sole consumer and its retired stub handlers are deleted in the
coordinated consumer change. No external caller uses these methods, and no
compatibility aliases or dual registrations are retained.

The orphaned request messages are removed, along with the orphaned
`RecordSubscriptionResponse`, `KeypairProof`, and `DeviceAuthProof` messages.
The response types `HostedNamespace`, `HostedRepository`, and
`AccessTokenResponse` remain because live RPCs still use them. `Entitlement`
and its supporting enums also remain because `WhoAmIResponse` still uses them.

## Breaking-change review

`buf breaking` against the previous published descriptor will fail on exactly
the five deleted methods and their deleted request/response message types. That
is expected and approved for the coordinated 0.14.0 pre-1.0 release. Per the
repository compatibility policy, this report is the named override for release
review; do not add wire shims or weaken the Buf `FILE` policy.

The orchestrator publishes 0.14.0 only after 0.13.0 is tagged and all consumers
are ready to repin. This proto PR deliberately does not bump package versions or
create a release tag.
