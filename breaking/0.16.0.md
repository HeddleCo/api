# 0.16.0 orphaned KeypairProof removal

This coordinated pre-1.0 cut removes one message whose only remaining traces
were doc-comment prose: `IdentityService` never carried `KeypairProof` on any
request or response, and no generated Rust or TypeScript consumer constructs
or reads it. Removing it deletes a message no wire path ever populated.

- `KeypairProof` (`heddle.api.v1alpha1`) is removed. Its type name is retired
  and must not be reused.
- The dangling `mint_biscuit_keypair` renewal-anchor prose that referenced it
  on `RegisterPublicKeyRequest.device_public_key`,
  `RotateCredentialRequest.proof_timestamp_seconds`, and
  `DeviceAuthProof.device_public_key` is scrubbed. No field, tag, or enum
  number changes as a result — those are comment-only edits.

The same batch additively fattens `InstallationRepository` (tapestry's repo
picker + weft#1817) with six new fields at the next free tags — `visibility`
(4), `description` (5), `default_branch` (6), `clone_url` (7),
`stargazers_count` (8), and `size_kb` (9). Additive fields are not reported as
breaking.

## Compatibility check

`buf breaking --against '.git#ref=origin/main'` reports exactly the intended
single message removal:

```text
proto/heddle/api/v1alpha1/identity.proto:1:1:Previously present message "KeypairProof" was deleted from file.
```

## Why no compatibility shim

All pre-1.0 consumers exact-pin the package and move in lockstep. Retaining an
unreferenced message solely to keep `buf breaking` silent would freeze dead
surface in the generated API for every consumer. `KeypairProof` carried no wire
traffic, so its removal breaks no live path; the break is documented here per
the repo convention rather than suppressed with a shim or a disabled check.
