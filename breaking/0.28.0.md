# 0.28.0 additive surface — first-class refs on PullReady

This release is **purely additive**: two new fields on an existing message at
their next free numbers. No RPC or message is removed, renamed, or renumbered,
and no advertised maturity is withdrawn. `buf breaking --against
'.git#ref=origin/main'` reports nothing — this document is a release record,
not a break report.

## First-class advertised refs on `PullReady` (heddle#1710 / weft#2055)

Luke lock 2026-09-05: no side-channel structs long-term. `PullReady` previously
carried only plan/objects/owner-genesis; advertised refs were smuggled as
hex-msgpack `heddle-pull-refs-v1` in `TransferCheckpoint`. heddle#1710 deletes
the client decoder and uses `ListRefs` `RefEntry` as an interim. The handshake
now carries the same type on `PullReady` so weft#2055 can drop the side channel.

On `PullReady` (`repo_sync.proto`):

- `repeated RefEntry refs = 11` — same type as `ListRefs`; one page, capped at
  `MAX_PAGE_SIZE` (200).
- `string head_thread = 12` — advertised HEAD; empty means unset.

No new message type. `RefEntry` remains the `types.proto` definition used by
`ListRefsResponse.item`.

## Why no compatibility shim

Everything is additive, so no consumer breaks and there is nothing to shim.
Older peers that omit tags 11 and 12 decode as an empty ref page and an unset
HEAD. Consumers still exact-pin `0.x` and move together to retire the
`heddle-pull-refs-v1` side channel.
