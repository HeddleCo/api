# 0.3.0 revision and thread identity cutover

This release is a coordinated pre-1.0 identity correction for API consumers.

- `StateId` is explicitly the immutable 32-byte physical revision identity.
  Consumers that put a 16-byte rewrite-stable `ChangeId` into a `StateId`
  field must resolve and send the corresponding physical state instead.
- Thread-bearing messages pair every renameable human-facing ref with an
  opaque, stable server-assigned thread id. Existing-thread requests use the id
  as identity; creation requests omit it only until the server assigns and
  returns it.
- Thread relation ids cover target, parent, child, and supersession edges so a
  rename cannot silently retarget or detach workflow data.
- Thread-policy patterns remain ref-based because they intentionally match
  human-facing names. A future monotonic per-repository thread sequence number
  is separate from the immutable id and is not introduced here.

The API package must publish before Weft changes its adapters and storage. Heddle
and other clients repin only after the server accepts and emits the 0.3
identities. No dual-registration or compatibility shim is provided.
