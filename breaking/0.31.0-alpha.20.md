# 0.31.0-alpha.20: exact HYBRID boundary acceptance binding

[api#318](https://github.com/HeddleCo/api/issues/318) revises the undeployed
HYBRID v1 signing layout in place for weft#2469 and heddle#1961. No deployed
records use these vectors. There is no old-layout reader or v2 compatibility arm.

Witness statement field 19 appends an explicit u32be optional-presence selector
and the complete `HostedWitnessBoundaryAcceptanceV1` when present. Genesis
payload field 5 similarly appends exact acceptance evidence; authority payload
field 6 appends its evidence list. OriginalAuthority includes explicit absence
or an empty evidence list in the canonical bytes. Existing v1 statement/payload
signatures, retirement leaves, archive roots and paths are therefore replaced.
Native original, acceptance, manifest, intent and receipt formats/IDs are unchanged.

BoundaryAcceptance requires the native acceptance ID, signed acceptance digest,
complete manifest/intent commitments and exact sorted per-original receipt
digests. Missing or substituted evidence fails `BoundaryAcceptance`. Publication
and landing require OriginalAuthority. The normative byte layouts and preimages
are in `docs/alpha-v2/import-authority-host-witness.md`.

`buf breaking --against '.git#tag=v0.31.0-alpha.19'` exits 0 with no output:
the protobuf changes are additive. Buf cannot detect this intentional canonical
signing-layout revision. Producers and consumers must use the regenerated v1
vectors together in the coordinated pre-release cascade.

The isolated native harnesses move from heddle 0.28.5/alpha.16 to 0.28.6/alpha.18,
the newest compatible published pair found by `cargo search` on 2026-10-03.
Although alpha.19 is published, 0.28.6 pins alpha.18 exactly; 0.28.7 is not listed.
This change does not publish or deploy the cascade.
