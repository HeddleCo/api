# 0.31.0-alpha.21: exact HYBRID preparation and delegation boundary

[api#321](https://github.com/HeddleCo/api/issues/321) revises the undeployed v1
Prepare/Commit contract in place. No deployed records use it; no v2 message,
old-layout reader or compatibility path is added. Release numbering remains
owned by the release workflow.

`PrepareImportJobResponse.proposal` field 1 changes from
`ImportJobDelegationV1` to `ImportJobPreparationV1`, the exact canonical frozen
projection. The response adds maximum validity duration, clock-skew allowance
and host preparation time. The browser completes and signs device key, parent
permission reference, signed genesis-binding digests and validity window.
Rust and TS compare frozen canonical bytes, parent non-amplification, branch
bindings, reservation/window bounds and signature before activation.
Existing completed-delegation signing layouts/domains and native IDs remain
unchanged. The fixture adds preparation commitment and Commit rejection/control
vectors and replaces the renewal preparation wire vector.

Producers and consumers must adopt the revised v1 schema/vectors together in the
coordinated pre-release cascade. This API change unblocks weft#2469 W2a; it does
not publish or deploy that cascade.

pair checked on 2026-10-03. API alpha.20 is published, but heddle 0.28.7 requires
alpha.19 exactly; neither harness substitutes unpublished or mismatched crates.
