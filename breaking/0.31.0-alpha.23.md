# alpha.23: HYBRID submission, scope negotiation and ref pinning

Closes [api#327](https://github.com/HeddleCo/api/issues/327). The undeployed v1
contract is revised in place, with no v2 format or compatibility execution path.
Rust and TypeScript package versions advance together to 0.31.0-alpha.23.

Prepare/sign/Commit is sufficient for initial import. Commit now requires the
existing ProviderRepository source selection and accepts optional canonical empty
base State bytes, at most 4096 bytes. Proof originals/envelopes/bindings and the
signed manifest are the only branch carrier. Its transaction activates epoch 1
and creates/returns the physical pending_operation atomically. Exact caller-scoped
client_operation_id replay returns the same receipt; changed inputs refuse.
ImportSource always refuses with FAILED_PRECONDITION and typed
IMPORT_SOURCE_REQUIRES_COMMIT. ImportBranchGenesis and its branches/import_authority
carriers are removed; those tags/names are reserved. RetryImportSource remains
the existing-operation retry route.

The caller selects every scope field. Prepare preserves those choices or returns
a typed refusal. Empty destination_version explicitly requests issuance of the
current opaque 32-byte CAS token; a supplied 32-byte token requires equality and
is echoed unchanged. GetImportConfiguration is a new authenticated, PoP-signed,
destination-writer unary read with converter versions, versioned option encodings,
complete canonical option choices/explicit defaults and host budget limits.
It is independent of provider inventory pagination and does not change the eight
existing import protocol gates. Prepare rechecks support and policy.

Known commit OIDs must be pinned. OBSERVE_AT_EXECUTION requires unavailable OID
knowledge, explicit review/selection and signed ref_disclosure=1; pinned mode
requires disclosure=0. The canonical ImportBranchLimitV1 layout appends that enum
as u32be. This changes all enclosing v1 scope/delegation signatures: consumers
must use the regenerated bytes and new signatures. Old signed bytes are never
reinterpreted or accepted by a compatibility verifier. Native original genesis
encoding, identity and creator signatures are unchanged. Helpers enforce the
marker, mode, exact scope and any independently supplied known OID; they cannot
prove UI consent or discover hidden local knowledge.

The 2026-10-04 contract amendments also revise undeployed v1 in place:

- Renewal parents cover remaining scope only. Their cancellation ID is stable
  within the same job/lineage/grantee; every new grant gets a fresh random 32-byte
  nonce, while retransmission preserves exact signed bytes. Original genesis
  permission/envelope bindings stay unchanged. Both revocation selectors remain
  effective.
- Cancel selects only the active delegation ID, fences by epoch, terminalizes the
  whole job, and resolves exact stored replay before current-state checks.
- Signature/scope-only expired predecessor recovery returns a distinct
  non-executable type bound to authenticated CAS state, including before any
  publication receipt. Current replacement authority and activation CAS are
  still mandatory.
- The caller lineage UUID is the reserved first physical operation ID. Collisions
  refuse and Commit receipt ID equality is enforced; request idempotency keys
  remain distinct.
- Browser signing preflight allows advertised bounded skew, returns no execution
  authority and gives no expiry grace. Host Commit chronology/expiry is unchanged.
- Documentation specifies heddle#1964's exact owner-history endpoint union
  (rotation without transfer uses the current hash only) and member/direct-owner
  native genesis envelope dispatch with its retained ImportSource method context.

The P2 private-source negative now differs from its public control only by
`private=true`; association/installation failures have separate negatives.
The signed disclosure pair uses direct-owner authority with consistent original
native genesis/signature/envelope bindings, avoiding a parent-scope mismatch.
Shared generated vectors and Rust/TS checks cover every executable amendment.
`conversion_options_digest` / `conversionOptionsDigest` remain exported and use
exact configuration option octets and the existing counted SHA-256 preimage.
