# 0.31.0-alpha.26 — HYBRID operation logical-job discovery

Closes #333. The seven API version files move together; harness pins remain on
the newest published compatible native 0.28.7 / API alpha.19 pair.

- Add `ImportOperationSubject.hybrid_job = 4`, a typed `HybridImportJobSelector`
  with `logical_job_id = 1` (exactly 16 bytes, not all zero). Its destination is
  `OperationRecord.ref.spool`, never another selector field or a guessed ID.
- Hosts must populate the durable association on every physical HYBRID attempt:
  initial, retry and renewal, including historical/terminal attempts. The
  destination/job pair stays stable. Non-HYBRID imports and attempts before
  association omit it; missing/unknown subjects likewise mean unavailable.
  Malformed present metadata rejects. No compatibility fallback or inventory RPC.
- Visibility follows the operation, independently of source-detail disclosure.
  The selector may be the only visible import-subject detail and grants no
  control authority. The state read stays destination-writer-only; control
  authorization, signed requests and current-state checks remain required.
- Rust/TS selector validators and operation-to-state-request helpers share 21
  wire/projection vectors: attempt stability, destination scoping, unavailable
  metadata, hidden source details, invalid widths/nil IDs and invalid destinations.

Signed HYBRID layouts, domains and canonical bytes are unchanged. All 56 existing
fixture files, including 174 HYBRID signed vectors, remain byte-identical to
alpha.25. Consumers must adopt the new population/projection semantics together.

`buf breaking --against 'https://github.com/HeddleCo/api.git#tag=v0.31.0-alpha.25'`
exits **0 with no output**. Buf checks wire compatibility; it does not enforce
durable association population, attempt stability or authorization semantics.
