# 0.31.0-alpha.27 — retained import custody and exact Resolve identity

Closes #335. All seven API version files move together. Harnesses keep the
newest published compatible native 0.28.7 / API alpha.19 pair.

- Add required-on-success `GetImportJobStateResponse.retained_source = 3`.
  Retain the accepted `ImportSourceSelectionV1` transactionally with the
  destination/job and exact signed provider/URL; return it only to current
  destination writers, including after client loss, expiry or connection
  revocation. It carries identifiers/visibility, never credentials or authority.
  Unknown/unauthorized jobs remain uniform NOT_FOUND; an authorized read without
  the complete durable association refuses UNAVAILABLE. No partial response or
  inventory-based recovery fallback.
  The association remains immutable across retries and renewals.
- Renewal Prepare uses that exact retained selector. Browser read/Prepare
  validation and the host source-preparation helper refuse replacement custody,
  repository/installation or visibility, even with a valid replacement grant.
  The Rust retained-context tuple and TS object now require the retained selector
  alongside verified predecessor/CAS state. No rebinding or compatibility path.
  Hosts still re-authorize current connection and exact repository/installation
  grants and selected-commit availability at Prepare and renewal activation;
  retained identifiers cannot restore revoked access.
- Resolve preserves selected URL, connection, repository ID, installation and
  visibility exactly. Only an empty public input repository ID may be completed
  to the exact requested URL. Canonical HTTPS validation never normalizes;
  `repo` and `repo.git` differ. Allowed transport redirects do not redefine the
  selected/signed identity; a changed resolved identity refuses. Rust/TS response
  validators enforce this boundary; network/SSRF/redirect policy remains a host
  gate. Name/default branch/ref/format observations may change independently.

Shared wire fixtures cover second-browser recovery, missing/malformed custody,
replacement grants, revoked connection, exact Resolve controls, public ID
completion, `.git` additions/removals, redirects and identity changes. Both Rust
and TS regression suites fail before the guards and pass with them.

Signed layouts/domains are unchanged. All **174 signed vectors**, **150 canonical
commitment vectors** and **4 raw commitments** remain byte-identical to alpha.26.
56 of 57 existing fixture files are unchanged; only the HYBRID fixture gains the
unsigned state-response selector, its descriptor and new unsigned test vectors.

`buf breaking --against 'https://github.com/HeddleCo/api.git#tag=v0.31.0-alpha.26'`
exits **0 with no output**. Buf verifies wire compatibility, not the new required
population, exact identity preservation, disclosure or current-grant semantics.
Consumers must adopt these semantics together; no backward compatibility.
