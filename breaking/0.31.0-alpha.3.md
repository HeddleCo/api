# 0.31.0-alpha.3 planned hard cut: password-unlocked client owner key

This is the intentional pre-1.0 breaking override for api#246, slice 1 of
weft#894. This branch does not change package versions or publish a release.
Consumers must update together before alpha.3 is released. No compatibility
field or server-rooted password route remains in the descriptor.

`buf breaking --against '.git#ref=origin/main'` reports these intended breaks:

- `PasswordProof` is removed. Raw password bytes no longer cross the API.
- `CompleteAuthenticationRequest.password = 6` is removed; tag 6 and name
  `password` are reserved. Password authentication now uses
  `ProvePasswordUnlock` and `CompleteAuthentication.password_unlock = 10`.
- `CompleteRegistrationRequest.password = 10` is removed; tag 10 and name
  `password` are reserved. Admitted, self-rooted signup uses
  `password_setup = 13` with the existing owner registration and device PoP.

Within this unreleased password contract, `PasswordChallengeMetadata.envelope_revision = 6`
and `PasswordChallengeProof.envelope_revision = 3` are removed and their tags
and names reserved. Begin no longer exposes an active or synthetic revision;
the server binds the revision to the one-use challenge and returns it only in
`PasswordUnlockContinuation`. The Prove signature transcript no longer contains
the revision. Challenge metadata now carries `auth_kdf_id` and `format_version`,
both pinned to 1. Signup verifier possession signs the domain-separated
registration challenge digest.

`CompleteAuthentication` now uses `AUTHORIZATION_EXISTENCE_HIDE` for all
methods. Weft's existing passkey and OAuth completion handlers must return
existence-hiding failures as well as the new password completion handler.

The new envelope is client encrypted and bounded to 4096 canonical bytes; the
complete setup is bounded to 4608 canonical bytes.
`BeginAuthentication` returns public verifier metadata and a challenge, never
the envelope. `ProvePasswordUnlock` returns the envelope, public owner state,
and a one-use continuation; it cannot return a session or credential.
Completion requires a current owner signature admitting the device, its
owner-signed mint-root attachment, and the existing request PoP. Password
setup PUT/DELETE requires an active owner signature and revision compare-and-swap.
Unknown format versions, KDFs, Argon2 costs, and malformed fixed-width fields
fail closed. The normal password completion result is `ClientOwnedCredential`.

This wire change does not convert existing server-rooted password accounts.
Weft must re-root or block those accounts before enabling the hard cut; the
remaining server migration and Tapestry ceremony are later implementation
slices. The release owner coordinates exact consumer pins and the alpha.3 tag.
