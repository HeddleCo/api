# 0.31.0-alpha.31

Adds Rust `verify_import_bundle_witnesses` and TypeScript
`verifyImportBundleWitnesses` to compose retained IMPORT proof verification.
The caller independently installs the descriptor pin, supplies its persisted
snapshot and verified historical owner contexts, and authenticates policy chains
through the mandatory heddle capability-verifier / WASM hook. The result contains
authenticated accepted CAS history and the updated durable snapshot. The npm
`@heddleco/api/v2/import-authority` export includes the helper.

Root replacement has **no previous-root overlap**. Explicit out-of-band pin
replacement advances epoch by one, invalidates old contexts (`StaleContext`), and
preserves accepted history, generation high-water, archive seals, tombstones,
job-key associations and clock floor. The previous root never authenticates new
responses. Replacements cannot reset generation or admit an older generation.
No backward-compatible bridge is provided.

Normatively clarifies owner authority expiry: derive it from the effective
selected owner state at verification time. Unclaimed deferred owners are bounded
by their positive claim deadline; accepted claims/deferral clearing are unbounded
(`2^63 - 1`). Historical verification uses the effective state at that time.
Signed permission/delegation windows remain in force.

Adds signed bundle rejection/control vectors, signed deferred-owner claim and
historical expiry vectors, and the fixture-only StaleManifest renewal-refusal
scenario (publication races the frozen signature; reread and obtain a new one).
All pre-existing signed/wire/commitment vectors and all other fixture files remain
byte-identical to alpha.30. Existing fields and signed domains are unchanged.
The additional job-control scope below adds protobuf response fields only.
All seven version files advance together to 0.31.0-alpha.31.

`buf breaking --against https://github.com/HeddleCo/api.git#ref=09827252a76d2b3b8509836a32e6fc8723d5ff49`
(alpha.30): exit 0, no output.

Owner decisions (2026-10-04) additionally specify Renew as authority activation
only (`receipt.applied`, empty resulting versions valid, no physical attempt),
frozen receipt replay and permanent logical cancellation/revocation. Retry
allocates a fresh host-generated UUID independently of its request ID and
atomically retains allocation, direct links and its `pending_operation` receipt.
Expired authority requires state read, remaining-scope Prepare, signing, Renew,
then a new Retry request with the replacement digest/epoch and eligible CAS.

Adds `ImportEligibleRetryTargetV1` and `ImportRetryUnavailableReason`, and fields
4/5 in `GetImportJobStateResponse.retry_availability`. A writer-only transactional
read provides a bounded eligible physical attempt/version or explicit reason.
Retry binds destination/job/lineage, operation CAS and active authority together.
This narrow writer disclosure does not change ordinary OperationService visibility.

Any current destination writer can Cancel without provider custody. CONNECTED
Retry/Renew require current ownership of the exact retained connection, exact
grants and selected-commit availability at admission/activation; subsequent
fetches use that authorized attempt, never the old initiator's credentials.
Public-git permits co-writer control subject to authority and all checks.

Rust/TS helpers and shared `import-job-control-alpha31.json` vectors cover control,
custody, bounded retry disclosure/admission, authority-only and pending receipts,
exact frozen replay and inclusive decoded Commit/proof bounds (2 MiB / 1 MiB).

TypeScript 39 failures (8 controls passed). After restoration: Rust 8/8 and
TypeScript 47/47 pass. These are API contract/helper checks; host transactional
allocation, persistence and credential fetches remain normative requirements.

Continuity: the pre-existing main fixture and every other pre-existing fixture

commitment and raw-commitment entries remain byte-identical. Version stays
0.31.0-alpha.31. `buf breaking` against alpha.30: exit 0, no output; only additive
messages/enum and response fields, with existing wire/signed layouts unchanged.
