## API changes

The fifth argument of bundle verification is now a resolver, with no default:

```rust
owner_at: impl FnMut(usize, Option<i64>)
    -> Result<ImportBundleOwnerExpectation<'a>, Reject>
```

```ts
type ImportBundleOwnerResolver = (
  delegationIndex: number, time: bigint | undefined,
) => ImportBundleOwnerExpectation | Promise<ImportBundleOwnerExpectation>;
```

Owner facts add `effective_from_unix_seconds: i64` and
`effective_until_unix_seconds: Option<i64>` (TS `effectiveFromUnixSeconds: bigint`,
`effectiveUntilUnixSeconds: bigint | undefined`). The key, identity, chain digest
and authority expiry MUST be independently verified for this effective interval.
The verifier chooses receipt times; the resolver selects effective owner state.
A resolver that falsifies authenticated history is outside the API trust contract.

Other signature changes:

- `verify_new_operation` / `verifyNewImportOperation` adds `committed_before` /
  `committedBefore` as its fourth mandatory argument.
- Reservation checks add a mandatory final `activation: bool` / `boolean`.
- Source Prepare adds `original_admission` / `originalAdmission` before retained
  state; it is required for renewal, absent for initial Prepare.
- Renewal request validation adds `original_admitted` / `originalAdmitted` and
  current time; renewal submission adds the admission boolean and uses the
  current owner's verified clock.
- Retry admission context adds `original_admitted` / `originalAdmitted`.
- New original-window/release helpers and local `Reject::OriginalWindowEnded` /
  `HybridContractError("OriginalWindowEnded")` support the host transaction.
