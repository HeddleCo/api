# 0.31.0-alpha.32: one import result-byte total and sibling jobs

Hard cut from alpha.31, API only; no compatibility reader, alias, deployment or
downstream implementation. Consumers must update together before HYBRID use.

api#351 adds whole-repository imports as disjoint sibling logical jobs into one
spool, each at most 256 branches and bounded by current host limits. Siblings may
Prepare/Commit/execute concurrently. The opaque `destination_version` fences
effective configuration, ownership and policy, and MUST NOT advance for other
imports. Hosts atomically reserve all refs and `(spool_uuid, full_ref, slot_id)`
keys across non-terminal jobs; duplicates refuse typed `DESTINATION_CONFLICT (5)`.
The slot number alone remains per ref, preserving existing canonical bytes.
Commit compares the current token and reservation under its activation lock;
stale activation returns `StaleContext`. Job manifests/epochs/budgets and Thread
frontiers retain their separate fences. Physical failure/expiry does not release
recoverable logical-job refs; terminal release preserves replay/accounting history.

Clients partition one click into separate Prepare/sign/Commit submissions and
allocate explicit positive result-byte headroom per sibling, each capped at host
maximum. No re-Prepare is needed solely for a sibling Commit/completion.
Changed configuration/ownership/policy needs client revalidation and new signatures.
The 2026-10-05 one-click import decision keeps signed `ref_disclosure` mandatory
for OBSERVE_AT_EXECUTION; its signature is explicit authorization and the audit
trail. Human presentation is client product policy, so clients may include
genuinely unknown-OID branches automatically and sign the disclosure on the
user's behalf without showing it or requiring branch selection or authorization
screens. Clients MUST pin every known OID, exclude a branch whose known OID
becomes unavailable rather than downgrade it, and never sign scope wider than
the user's action. Unsigned or missing disclosure and silent downgrades always
refuse. Protocol and signed/wire layouts remain unchanged by this clarification.
See the [normative contract](../docs/alpha-v2/import-authority-host-witness.md#whole-repository-sibling-jobs-in-one-spool-api351)
for reservation lifetime and renewal behavior. The new frozen
`import-sibling-jobs-alpha32.json` corpus exercises sequential/concurrent siblings,
post-completion admission and fail-then-pass conflicts in Rust/TS. Every existing
fixture/vector for the sibling change was unchanged from `b9f590afc23f2b37f20b34af09f5cb2389a8c6ad`.
The owner decision of 2026-10-05 removes the fixed protocol byte cap. The signed
`max_result_bytes` authorizes what the server-held job key may write under the
user's delegation; it bounds the blast radius of a compromised or buggy worker
and is not a storage quota. Storage is billed separately. The host advertises
an operator-configurable positive u64 maximum that may be very large. Prepare
and Commit refuse totals above the CURRENT advertised maximum, including a
maximum lowered since Prepare. Authority remains per job and narrow-only:
remaining = total − consumed across renewals/retries, never reset.

No schema field, canonical layout or package version changes for this decision.
The replaced negative is above the advertised host maximum; new positives cover
50 GiB with a 1 TiB host maximum, u64::MAX, manifests and signed owner delegation.
Both Rust and TS consume the same frozen vectors. The host-cap continuity
manifest records the sole retired negative, additions and hashes of every
other fixture record/file against `2ec7b92e6dfcb1c42e96c499e967558121f963a0`:
[0.31.0-alpha.32-host-max-vectors.json](0.31.0-alpha.32-host-max-vectors.json).

`ImportBranchLimitV1.max_result_bytes` (tag 9) and
`ImportBudgetLimitsV1.max_branch_result_bytes` (tag 4) are deleted and reserved.
The remaining branch fields keep their numbers, including `ref_disclosure = 10`.
`ImportPermissionScopeV1.max_result_bytes = 8` is the **one** positive total,
any positive u64, alongside `max_operations = 7`. Refs, stable slots,
genesis/target/frontier identity and signed source choices remain exact.

Removing the branch u64be changes canonical scope, parent, preparation, manifest
and delegation bytes. Every dependent signature/digest, operation reference,
result manifest, witness leaf, archive seal/proof and containing request/bundle
must be regenerated. Existing v1 domains are revised in place for the undeployed
format; there is no old-byte fallback. Original native records, unrelated owner
records, content/frontier commitments, native witness records and all other
unaffected vectors retain their exact bytes.

The exhaustive existing-vector change/retirement list is
[0.31.0-alpha.32-vectors.json](0.31.0-alpha.32-vectors.json), grouped by fixture
and vector collection. It identifies 617 changed existing vector records, eight

and fixture file. Only `native-host-witness-v1.json` import dispatch carriers `import_complete`
and `import_without_delegation` change; every native authority/witness vector

Remaining bytes are the previous total minus consumption for its covered slots;
already removed historical slots are not charged twice. Renewed parents and
certificates can only narrow. Hosts retain original job totals and accounting by
`(permission digest, logical job)` across keys, delegations, renewals and retries.
Witness composition checks cumulative original, certificate and permission totals.

Discovery adds advisory `ProviderRepository.size_estimate_state = 12` and
`git_size_kib = 13`. UNKNOWN (0) requires zero; AVAILABLE (1) can be zero for an
empty repository. Connected GitHub reports approximate Git size in KiB (1024
bytes); public Git reports UNKNOWN. These are not result bytes or authority.
Clients compute total = size estimate × headroom (rounding up with checked or
widened arithmetic), capped by `GetImportConfiguration.limits.max_result_bytes`;
for UNKNOWN they use the current advertised host maximum. Users never set it. No cheap per-branch estimate exists.

The alpha.31 P3 fixes select the native creator signature by public key, add
`ImportRetryUnavailableReason.ORIGINAL_WINDOW_ENDED = 7`, and return typed
`evidence` (`Recovery`/`Witnessed` in Rust, `"recovery"`/`"witnessed"` in TS).
An unwitnessed activation tail is recovery even with earlier witnessed history.
A never-admitted original whose exclusive window ended needs a new logical job;
Renew cannot replace its original genesis authority. Stored receipt replay stays
an acknowledgement. The classification helpers consume authenticated host facts.

Consumer additions before review (PR #352 resume note 2) keep alpha.32:

- `GetImportJobStateResponse.control_availability = 6` adds required, caller-relative
  Retry/Renew/Cancel availability. `ImportJobControlAvailabilityV1` contains three
  `ImportControlAvailabilityV1` values with `available=true` or a known nonzero
  `ImportControlUnavailableReason`. Connected co-writers see
  `NOT_CONNECTION_OWNER` for Retry/Renew; Cancel remains destination-writer-only.
  The host computes advice at read time and still enforces all checks at admission.
  It reveals only the caller's relationship, never other accounts' connection data.
- Bundle verification now takes `ImportBundleOwnerExpectation` values **without**
  `now_unix_seconds` / `nowUnixSeconds`. Rust's `From<ImportOwnerExpectation>` drops
  the former time during migration; TS uses `Omit<ImportOwnerExpectation,
  "nowUnixSeconds">`. The verifier derives first-publication/initial-admission times
  internally from authenticated receipts and returns `owner_check_times_unix_seconds`
  / `ownerCheckTimesUnixSeconds`. Existing live-work APIs keep their host clocks.
- `VerifiedImportBundleWitnesses.snapshot` is now optional (`Option` / `undefined`),
  with explicit `snapshot_advanced` / `snapshotAdvanced`. Recovery without a new
  authenticated set returns the input snapshot unchanged. With no input and no
  set there is no snapshot to persist. A new authenticated set may advance its
  high-water mark and clock floor; recovery never adds unwitnessed job history or
  job-key associations. The CAS read state and typed evidence remain separate.

The scheduled-Commit tests now expect empty durable admitted history during
zero-admission recovery, and assert the explicit advancement result. The old
`caller_chosen_owner_time` scenario now verifies the internally derived times
rather than expecting a caller-time mismatch refusal. Its frozen bytes and all
other existing fixture bytes remain unchanged against
`36b06262d45209a8ab4400164827de05e8a83043`; the new shared consumer corpus is
`tests/fixtures/import-consumer-alpha32.json`. No signed canonical layout changes
for these additions. See the normative witness-composition and writer-control
contracts for persistence, reason priority and admission requirements.
