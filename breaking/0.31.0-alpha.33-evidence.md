The DIRECT host-budget tests call `check_import_publication_budget` /
`checkImportPublicationBudget` with committed = {op1}. They assert that op2 is
exactly one byte over the remainder (Scope), or an exact fit (accept), with one
operation still available. Removing just the byte check produces **Ok/ACCEPT**;
no other budget checks are disabled. Full-ref tests isolate the ref collision
from target/genesis collisions, so each sibling predicate is independently tested.

The new signed `p1_p3_outside_window` vector has equal P1/P3 milliseconds,
transaction and executor, with P1 preceding P3. The DIRECT pair test rejects
Expired; removing only its window check produces **Ok/ACCEPT**, not another
rejection label. The complete bundle also rejects this vector. A complete bundle
cannot accept an equal-time out-of-window P1/P3 pair after disabling only P1
verification: initial historical-delegation and P3 publication verification
independently reject that same time. Those checks remain intact. The direct pair
checker isolates the P1 guard without weakening the full verifier.

Missing TS `operations[1].body` gives `HybridContractError("Canonical")`; the
unsafe mutation gives TypeError. Rust parity is a typed Canonical refusal; its
mutation changes the error to Scope. All 35 status/reason combinations are tested,
including valid controls. Signed direct-owner windows at 7 days and 24 h pass;
7 days + 1 second and `[0, i64::MAX)` refuse. A host D above 7 days refuses even
with a shorter valid certificate, in both Commit verification and browser preflight.

Logs are written to `/tmp/api-alpha33-guards/` and
`/tmp/api-alpha33-rust-guards/` as `<guard>-red.log` and `<guard>-green.log`.
The continuity gate was also tested with one deliberately wrong manifest hash:
exit **1**, then exact restoration and exit **0**. No signed fixture bytes were
edited for that demonstration.
