# 0.31.0-alpha.33: one-shot HYBRID imports

This API-only release is a hard cut from alpha.32 (`77f73219`). Regenerate both
Rust and TypeScript bindings and update all peers together. There is no old
reader, alias, shim or alternate signed layout. Runtime implementation and
deployment in heddle/weft/tapestry are outside this release.

## Deleted protocol surface

- RPC `IntegrationService.RenewImportJob` and its request/proof profile.
- Messages `RenewImportJobRequest`, `ImportJobRenewalV1`,
  `SignedImportJobRenewalV1`, `ImportJobCasStateV1`,
  `ImportControlAvailabilityV1`, `ImportJobControlAvailabilityV1`; enum
  `ImportControlUnavailableReason`.
- `PrepareImportJobRequest.renew_logical_job_id` (6),
  `PrepareImportJobResponse.renewal_state` (3),
  `ImportJobDelegationV1.predecessor_delegation_digest` (17),
  `ImportJobPreparationV1.predecessor_delegation_digest` (12),
  `ImportPublicProofBundleV1.renewals` (8) and `.member_permissions` (18).
  Deleted numeric tags are reserved; no deleted field-name alias is retained.
- The old GetImportJobState response's `state`, `retained_proof`,
  `retained_source` and `control_availability` fields, including retained
  activation history, original-admission facts and manifest CAS.
- Retry reason `ORIGINAL_WINDOW_ENDED` (7); tag 7 now means `AUTHORITY_EXPIRED`.
  Rust/TS refusals `RenewalFork` and `OriginalWindowEnded`, renewal domain,
  verification/signing, predecessor branding, renewal replay/response helpers,
  original-admission expiry classifiers and control-availability calculators.

The exact deleted and changed public Rust/TypeScript declarations, with before
and after signatures and struct/interface fields, are in
[the API surface inventory](0.31.0-alpha.33-api-surface.md).

`StaleManifest` stays for a missing digest-addressed publication manifest.
`CommittedSlot` stays for excluding already committed slots; `SlotConflict` for
nonidentical slot replay; `StaleContext` for destination/Cancel/Retry fences.
These have live non-renewal consumers. `remaining_import_scope` /
`remainingImportScope` stay solely for cumulative publication budgeting, subtracting
every committed slot under the one delegation. Their signatures are unchanged.

## Changed protocol and verifier surface

Every logical job has exactly ONE user-signed delegation and at most one typed
member permission. `ImportPublicProofBundleV1.delegations` remains a repeated
field but accepts exactly one element. Its optional singular `member_permission`
remains for device delegation; direct owner authority uses no parent. Canonical
delegation bodies now have fields 1–16 and preparation bodies fields 1–11, ending
at cancellation_id, with no predecessor bytes. All affected signatures and
dependent digests change. Public proof manifests are bounded to 256, replacing
320; there is no 63-renewal or multiple-delegation limit/workflow. Operations and
bytes sum over all publications under that sole certificate and its parent;
Retry never resets the sum. An unfinished job is terminal when its window ends.
Remaining branches require a NEW logical job, with its own one-click delegation.

GetImportJobState is a writer-only snapshot, at most 4096 encoded bytes:

| Field | Rust generated field/type | TS generated field/type |
| --- | --- | --- |
| 1 | `status: i32` (`ImportJobStatus`) | `status: ImportJobStatus` |
| 2 | `active_cancellation_id: Vec<u8>` (32) | `activeCancellationId: Uint8Array` (32) |
| 3 | `authority_epoch: u64` (positive) | `authorityEpoch: bigint` (positive) |
| 4/5 | `retry_availability: Option<get_import_job_state_response::RetryAvailability>` | `retryAvailability: {case: "eligibleRetryTarget", value: ImportEligibleRetryTargetV1} \| {case: "retryUnavailable", value: ImportRetryUnavailableReason} \| {case: undefined, value?: undefined}` |
| 6 | `active_delegation_digest: Vec<u8>` (32) | `activeDelegationDigest: Uint8Array` (32) |

The validator requires a populated availability arm. Status is ACTIVE (1),
COMPLETE (2), CANCELLED (3), REVOKED (4) or EXPIRED (5). Retry targets require
ACTIVE; UNSPECIFIED/unknown status and reason values refuse. The digest stays
because existing Retry requests fence on it. Cancel needs the cancellation ID
and epoch. Neither Fetch nor export consumes retained_proof/retained_source from
this response: each carries its own `ImportPublicProofBundleV1` and public native
originals. Retry's host gate takes source custody and cumulative manifest as
separate receiver-owned `ImportRetryAdmission` context fields. They are never
authority supplied by the state-read caller.

Changed helper call shapes:

- Rust `prepare_import_source_scope` / TS `prepareImportSourceScope`: five
  arguments (request, current source, connection provider, configuration,
  current destination version); delete both original-admission and renewal inputs.
- Rust `check_import_spool_reservations` / TS `checkImportSpoolReservations`:
  four arguments (spool UUID, logical job ID, scope, complete inventory); delete
  the activation flag and mandatory Prepare-time exclusive inventory requirement.
- Rust `verify_import_bundle_witnesses` resolves
  `FnMut(Option<i64>) -> Result<ImportBundleOwnerExpectation<'a>, Reject>`;
  TS `ImportBundleOwnerResolver` is
  `(time: bigint | undefined) => ImportBundleOwnerExpectation | Promise<ImportBundleOwnerExpectation>`.
  Delete the delegation-index argument. The authenticated first P3 supplies the
  certificate verification time; each P1/P3 independently resolves owner key,
  effective expiry and the interval containing its authenticated time.
  None/undefined is only time-free, non-executable recovery. Result
  `accepted_history` / `acceptedHistory` is the cumulative result manifest, and
  `owner_check_time_unix_seconds` / `ownerCheckTimeUnixSeconds` is singular.

## P1/P3 and window rules

For each branch, P1 first admission and P3 publication occur in the SAME host
transaction. Their `observed_at_unix_millis` and `host_transaction_id` MUST be
equal, with `P1.admission_order < P3.admission_order`. Both become visible
atomically. Every P1 requires that branch's P3, and every published branch
requires its original genesis/envelope and P1/P3 receipts. There is no genesis-only
Thread or admitted-but-unpublished state. Conversion start confers no admission.

P1 and P3 witnessed time MUST fall in the exact half-open delegation window
`[not_before, expires_at)`. Owner key, effective owner expiry/interval, parent,
policy and revocation are checked live at that time. No testimony before
eligibility or expiry grace. Clients set not-before approximately now; scheduled
Commit admission semantics are removed. The existing skew allowance still
permits a small future not-before at Commit, with execution/testimony gated on it.

There is **no fixed protocol duration cap**. Duration is bounded by the positive
host-advertised `max_validity_duration_seconds: u64`, the signed nonnegative
i64 endpoints and effective owner/parent authority expiry. A host advertisement
of **86400 seconds (24 h)** is supported and accepted when authority covers it.
The unchanged **3600-second Prepare reservation** is a separate limit; skew is
unchanged. Widened arithmetic handles extreme u64 advertisements safely.

## Smaller host requirements and Git roots

Clients MAY prepare/commit sibling jobs sequentially or concurrently; each job
is limited to 256 branches, with no spool-wide branch limit. Hosts MAY reserve
refs during Prepare or enforce a unique `(spool, full_ref)` index over
non-terminal jobs at Commit/activation. Both atomically refuse duplicates with
DESTINATION_CONFLICT. Prepared key/proposal custody remains mandatory, and
conflicting active target/genesis identities still refuse.

UNKNOWN is always a permitted size answer, including connected GitHub.
Repository API size observation is a MAY; UNKNOWN carries git_size_kib=0.
Destroying encrypted/live job keys at certificate-terminal is expected behaviour;
seven days after terminal is the absolute maximum, including replicas/backups.
Restore must apply key-deletion tombstones before workers; backup retention must
not extend that maximum. Public proofs and receipts remain indefinitely.

[Git-root PR #354](https://github.com/HeddleCo/api/pull/354) is included via
`origin/main` (`ab1aec46`), preserving its final normative text. Each branch has
one converted operation. Git ancestors remain State content, carrier-selected
Git parents are independent of native frontier parents, and an empty frontier
keeps the Git root parents as-is. Native authorization/budget gates still apply.

## Consumers delete

Delete Renew UI/control/profile handling, replacement delegation/key signing,
renewal types, domains, predecessor state, authority-only activation and renewal
replay bookkeeping. Delete retained state-read proof/source and availability
reason handling. Update generated field access to the minimal state, drop owner
resolver indexes and plural owner-time results, and regenerate current signed
layouts without accepting alpha.32 bytes. Keep Retry's fresh host UUID, exact
replay, source custody and authority fences; keep Cancel independent of source
access. On certificate expiry fence unfinished work and destroy keys; re-import
remaining branches as a fresh logical job. Issue P1 only with publication.

notices remain archival; no active generation or verification uses their corpora.
