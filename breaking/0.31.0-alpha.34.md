## Exact proto and API surface

Package `heddle.api.v1alpha2`, shared definitions in `import_authority.proto`:

```proto
enum ForeignDependencyOrigin {
  FOREIGN_DEPENDENCY_ORIGIN_UNSPECIFIED = 0;
  FOREIGN_DEPENDENCY_ORIGIN_IMPORT = 1;
  FOREIGN_DEPENDENCY_ORIGIN_NATIVE = 2;
}
message ForeignDependencyV1 {
  uint32 format_version = 1;
  ForeignDependencyOrigin origin = 2;
  bytes thread_genesis_digest = 3;
  bytes signed_native_digest = 4;
  uint64 prefix_admission_order = 5;
}
```

`NativePublicProofBundleV1.foreign_dependencies` is repeated field **13**;
`ImportPublicProofBundleV1.foreign_dependencies` is repeated field **23**.
Both use `ForeignDependencyV1`. The value of `format_version` is exactly 1;
origin must differ from its carrier. Digests are exactly 32 bytes. Entries are
strictly raw-digest sorted, unique by signed-native digest, bounded by the 1 MiB carrier and all
referenced by exact signed original and Thread. Existing bundle/payload bounds
remain. The entries are unsigned references, never nested carriers or permission.

[The generated API inventory](0.31.0-alpha.34-api-surface.md) lists exact Rust
fields, enum variants and TS fields/schemas. All existing public runtime function
entry-point signatures stay unchanged. The new public landing role helpers and
receiver role inputs are listed in that inventory. Both validators enforce foreign references in native
P2 dependency closure, P4 source/review closure and native dependency resolution,
and symmetrically in import bundle history. Import witness snapshots retain exact
foreign entries cumulatively. No RPC, error vocabulary, mandatory feature,
signed original/purpose payload, signing domain or witness leaf changes.

## Receiver contract

Each Thread keeps one immutable IMPORT or NATIVE carrier for life. Fetch sends
foreign original PREFIXES first, one carrier per message.
`prefix_admission_order` selects the authenticated own-origin P3/P2/P4/P1 cutoff;
exact Thread and signed-native digests identify its endpoint. Earlier prefixes
exclude later foreign obligations, so C→M followed by M→C is replicable by a
fresh receiver. Install earlier prefixes, retain exact signed evidence, and extend
the same immutable origin using ordinary high-water checks. Reject cycles only
at original granularity. LocalKey native work selects its ownership-proof cutoff
and exact causal closure; no synthetic P2 is introduced. A dependent install requires the
receiver's already durable original, origin/genesis and exact P3 import or native
admission binding, with witnesses rechecked against independent current trust.
A missing stage rejects with `Scope` and changes no dependent state; no fallback.
`validate_carriers` and `validateNativeWitnessCarriers` are unchanged: two carriers
on one message still reject with `Protocol` before staging.

Landing selects the source role: Account uses `native_authority`; LocalKey import
requires its exact verified import binding and matching job publisher or returns
`ImportPermission`; hosted integration requires P4. A job-key landing request
rejects with `KeyRole`. References never grant the job landing power.

The normative receiver, transport and role rules are in
[native-host-witness.md](../docs/alpha-v2/native-host-witness.md#foreign-dependencies-alpha34-hard-cut)
and [import-authority-host-witness.md](../docs/alpha-v2/import-authority-host-witness.md#foreign-dependencies-alpha34-hard-cut).
Multiple import jobs on one Thread are explicitly DEFERRED; exactly one delegation
remains required. Witness subjects (P2 original/P4 execution) MUST have in-carrier
geneses; only dependencies/source/reviews may be foreign.

The Rust and TS staged receiver tests are executable API conformance models;
they do not claim a downstream database, Fetch or production installer run.
The Rust model also uses the published native codecs/owner verifier to check
actual job Captures, exact P3 frontier/content bindings, native child authority,
landing request commitments, source/result State and causal parent validity.
