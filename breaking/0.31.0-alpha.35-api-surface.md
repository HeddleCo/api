# Alpha.35 API surface inventory

Baseline: alpha.34, `ea3f713a`. API-only semantic hard cut; no compatibility shim.
No protobuf field, message, enum, RPC, mandatory feature, signing domain, signed
layout, witness purpose/set/statement or retirement leaf changes. `identity.proto`
changes normative comments only. Existing fixtures remain byte-identical.
All seven manifest/lock files move together to `0.31.0-alpha.35`.

## Existing verification entry points

Signatures remain unchanged:

- Rust `native_witness::verify_genesis_authority`, `verify_genesis_payload`,
  `validate_public_bundle`, `verify_bundle_witnesses`.
- TS `verifyNativeGenesisAuthority`, `signNativeGenesisAuthority`,
  `verifyNativeGenesisPayload`, `validatePublicNativeBundle`,
  `verifyNativeBundleWitnesses`.
- Rust `import_authority::validate_public_bundle`, `verify_import_bundle_witnesses`
  and TS `validatePublicBundle`, `verifyImportBundleWitnesses`.

Account genesis binding now matches the author's envelope root account to the
genesis Account, independently of the Spool lineage. Equal author/Spool accounts
require exact immutable owner-ID equality. Public bundle checks additionally
decode native P2/P4 actor envelopes, apply that hard rule and enforce the exact
selected policy's publisher/mint-root key cuts. Native P1 does the same, including
the publisher cut for an empty-envelope LocalKey genesis. Import P1 remains the
existing import authorization shape; it is not reinterpreted as a native TCA.
Full actor/token-subject selection, owner history, Biscuit, role fencing, boundary
and causal verification remain required in the downstream native verifier.

## Added Rust surface

New public module `heddle_api::writer_authority`:

```rust
pub fn decode_authority(envelope: &[u8]) -> Result<api::ThreadControlAuthority, Reject>;
pub fn verify_account_binding(
    authority: &api::ThreadControlAuthority,
    actor_account: &[u8], spool_account: &[u8], spool_owner_id: &[u8],
) -> Result<(), Reject>;
pub fn check_writer_keys(
    authority: &api::ThreadControlAuthority,
    publisher_key_id: &[u8], revoked_key_ids: &[Vec<u8>],
) -> Result<(), Reject>;
pub struct RetainedMintRootExpectation<'a> {
    pub account_uuid: &'a [u8],
    pub mint_root_public_key: &'a [u8],
    pub issuer_state_hash: &'a [u8],
    pub issuer_sequence: u64,
    pub issuer_public_key: &'a [u8],
    pub issuer_retained_mint_authority: bool,
    pub admitted_attachments: &'a [api::SignedOwnerMintRootAttachment],
    pub now_unix_seconds: i64,
}
pub fn verify_retained_owner_mint_root_attachment(
    signed: &api::SignedOwnerMintRootAttachment,
    expected: &RetainedMintRootExpectation<'_>,
) -> Result<(), Reject>;
```

`check_witness_writer` is crate-private. The expectation contains **independently
verified input facts**, not a self-authenticating owner-history type. The caller
resolves the issuer and its recovery status through the native owner verifier.
Issuance supplies the host's exact durable inventory; receipt supplies only exact
attachments from authenticated, matching P1/P2/P4 payloads. The helper checks exact
inventory membership, issuer/account/mint binding, interval and owner signature.
It neither enrolls an old certificate nor verifies a sealed Biscuit.

`@heddleco/api/v2` barrel and the new public package subpath

Same input-provenance requirements as Rust. `checkWitnessWriter` checks reference
and key-cut facts; the caller must authenticate the policy and owner history.
Existing `verifyOwnerMintRootAttachment` remains the current-owner enrollment
check. Historical certificates use the explicit retained helper and inventory;
there is no permissive fallback from current enrollment verification.

## Errors and trust

Reuse `GenesisBinding` for root-account/genesis mismatch, `Root` for equal-account
owner-ID mismatch and missing/unknown/recovered retained issuer/inventory,
`Revoked` for actor key cuts, `Expired` for certificate interval, and `Signature`
for an invalid original certificate signature. No new error vocabulary or trust
anchor is introduced. The host statement testifies write-role eligibility,
prior retained attachment admission and P4 landing-policy satisfaction, including
required CI checks. Native Review IDs alone inhabit P4 review evidence.
