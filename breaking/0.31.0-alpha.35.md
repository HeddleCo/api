# 0.31.0-alpha.35: HYBRID writer authority

Owner decision, 2026-10-05: QA7 option B and QA9 option B, with the retained
paired-device bug bundled. API-only hard cut from alpha.34 (`ea3f713a`), with no
compatibility shim. Delivery order is API → heddle → weft/browser; this PR does
not deploy the downstream implementation or publish a tag/package.

Resolve three things independently: (i) Spool governance lineage and policy,
(ii) the author/actor's own account root/history/device authority, and (iii) the
actor's required write role, attested by the host P1/P2/P4 statement under its
issuance fence. The native P1 binding matches the envelope root account to the
immutable genesis Account. If the actor account equals the Spool owner account,
immutable owner IDs must match exactly. Apply the bound owner-signed Spool
policy's `revoked_key_ids` to actor publisher and mint-root keys.

Ordinary Rotate preserves exact admitted device certificates, including the
attachment inherited by a paired leaf. Hosts supply durable pre-transition
inventory; receivers use exact authenticated P1/P2/P4-attested attachments.
Verify issuer state/sequence/key through the actor's verified history with no
Recover since. Recover clears prior retained authority. A valid old-owner
signature on a new certificate cannot prove prior admission.

P4 `HostedIntegration.review_evidence` contains only native Review operation IDs.
The host enforces required CI checks and the P4 statement testifies satisfaction
of the bound landing policy at execution. Check evidence may remain host-side
for audit; receivers cannot prove CI verdicts or completeness offline.

Normative rules and inventory provenance:
[native contract](../docs/alpha-v2/native-host-witness.md#writer-authority-iiiiii),
[import contract](../docs/alpha-v2/import-authority-host-witness.md#writer-authority-iiiiii).
[The exact API surface inventory](0.31.0-alpha.35-api-surface.md) lists added
helpers and unchanged entry-point signatures. No signed-byte or wire-layout
change is made. Buf's FILE check cannot detect these semantic authority changes.

Seven requested positives, exercised in Rust and TS at the API layer:

- `cowriter_start_thread`: original genesis + second creator signature, with
  independently signed co-writer root, distinct publisher/mint key and
  own-account sealed token. New native records pass the published native codecs;
  their embedded authority digests use the native typed BLAKE3 domain, distinct
  from the outer witness-envelope SHA-256 commitment.
- `cowriter_capture_own_thread`, `cowriter_capture_owner_thread`: P2 original
  signatures, witness signature/payload commitments and actor-account binding.
- `cowriter_review`: the same checks for native Review metadata.
- `cowriter_land_request`: original LandThread request proof, P4 commitments
  and own-account authority envelope. Full verified token-subject selection is
  a downstream native check.
- `cowriter_claim`: exact local-owner/accepting-publisher signatures and P2.
- `paired_after_rotate`: exact admitted historical issuer certificate, signature
  and interval with independently supplied retained-issuer facts/inventory.

Requested negatives, each rejected and followed by a passing control:

- `self_signed_owner_uuid` (`Root`).
- `account_mismatch` (`GenesisBinding`).
- `actor_publisher_revoked`, `actor_mint_revoked` (`Revoked`); the key-cut test
  uses distinct publisher and mint IDs so each guard is independently exercised.
- `attachment_before_recover` (`Root`, selected verified issuer is not retained).
- `forged_old_owner_certificate` (`Root`, valid old-owner signature but no exact
  prior-admission inventory membership).
- `unknown_issuer` (`Root`), including when the exact bytes appear in inventory.

Additional signature negative: `invalid_old_owner_signature` (`Signature`),
including when its exact bytes appear in inventory. Public-bundle controls
`cowriter_start_bundle`, `cowriter_import_bundle` and negatives
`native_actor_key_revoked`, `import_actor_key_revoked` prove that both entry
points enforce the selected signed policy cut.

## Exactly what follows the heddle release

`tools/hybrid-native` retains its published heddle 0.28.7 / native-api alpha.19
pins. It does not yet have the new independent actor resolver or the HYBRID
retained-inventory path. **Full native conformance** for all seven named positives
above must follow a compatible published heddle release: P1 StartThread;
P2 Capture on own and owner's Threads; Review; P4 LandThread requester resolved
from the verified sealed token subject; co-writer claim; paired-device P1/P2/P4
after a real signed Rotate. The API vectors do not assert full native model,
Biscuit, causality, role fencing or transactional admission.

The downstream negative suite must likewise run the six requested authority
cases through full native/host/receiver verification: owner-UUID impersonation,
root-account mismatch, publisher/mint revocation, a real signed Recover cutting
prior attachment authority, a newly signed old-owner certificate absent from
the host's durable inventory, and an unknown issuer. The API tests already cover
their portable bindings/key cuts/certificate predicates, using explicit verified
issuer input fixtures for Rotate/Recover. Host grant removal/Reader/epoch races,
live landing required-check enforcement and durable receiver rollback belong to
heddle/weft. This release does not claim those runtime tests.

## PR #358 fix round

Policy contents are now checked in the shared chain walker. Each selected record
must carry a body whose recomputed state hash matches its commitment; successor
revocations must contain every predecessor revocation. Duplicate/reordered policy
records and duplicate owner-history hashes reject. The Spool account comes from
signed identity/transfer context. P2/P4 equal-account envelopes must match the
exact Spool owner ID, and receivers must use the new verified actor binding
helpers. Claim/resolution counterparties are cut by the same revoked-key list.
P4 review evidence accepts only native Review operations.

The raw retained expectation interface has been removed. Issuer authority is
derived from verified OwnerHistory, and prior admission is extracted from an
authenticated statement and exact payload. Both results are opaque. Rust and TS
strict-decode raw attachment bytes. See the updated [API surface](0.31.0-alpha.35-api-surface.md)
and receiver requirements for exact signatures and mandatory preconditions.
