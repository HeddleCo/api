# 0.31.0-alpha.36: boundary acceptor writer-authority bug fix

API-only hard cut from alpha.35 (`dafbea26`). BoundaryAcceptance (basis 2)
authorizes the current accepting party. Alpha.35 incorrectly applied the bound
Spool policy's key cuts to the immutable original publisher and mint root.
A since-revoked original therefore failed even when a distinct, currently
unrevoked party signed a valid acceptance.

Both Rust and TypeScript public native/import bundle validators now select the
acceptance from the exact witness-bound payload and match its complete boundary
binding. The acceptance has exactly one signature, whose public key must equal
its signed `accepting_publisher`. Its signed `accepting_author` selects the account,
Spool and complete authority envelope, including mint root and sealed credential.
The envelope's native authority digest must match. Root-account binding, the
equal-account immutable-owner-ID hard rule, and the selected owner-signed policy's
publisher/mint cuts apply to this accepting party.

Original signatures, envelope commitments and provenance bindings remain on
their existing verification paths. Original keys and ownership counterparties
are not cut for basis 2. Ordinary basis 1 is unchanged, including import P1's
existing delegated authority path. The witness continues to name the original
publisher; no historical non-revocation is asserted. No wire layout, signed
bytes, older vector, package tag or downstream repository is changed.

The portable TypeScript import carrier validator remains synchronous. Callers
must authenticate originals, acceptance signatures and payload commitments with
`verifyWitnessPayload`, then perform full native owner/history/Biscuit verification.
Native permission, credential revocation, manifest membership, causality and
host role fencing remain mandatory on the selected accepting authority; decoding
an envelope does not authenticate those facts. Rust additionally authenticates
the complete boundary evidence during the writer selection.

Normative contracts: [native](../docs/alpha-v2/native-host-witness.md),
[import](../docs/alpha-v2/import-authority-host-witness.md).

## Regression and guard evidence

Red checkpoint `38760f8e`: against alpha.35, Rust exited 101 (0 passed, 2 failed)
and TypeScript exited 1 (4 passed, 20 failed). The revoked-original positive
failed with `Revoked`; revoked acceptors and forged accepting publishers passed.
The final baseline rerun with 28 TS tests exited 1 (5 passed, 23 failed);
restoring the fix passed all 28. Rust again failed both tests (101), then passed
both (0). The final frozen corpus adds distinct acceptor publisher/mint keys and separate
cuts for each, with native/import P1 and P2 coverage. It also checks account
mismatch, owner impersonation and unchanged ordinary revocations.

`tools/verify-alpha36-guards.py rust` and `ts` each disable nine selections or
checks, require a real failing test, restore the exact file, and require a passing
run: basis selection, acceptance signer, account/owner binding, publisher cut,
mint cut, native P1/P2 selection, import selection and the import P1 boundary hook.

`tools/verify-alpha34-vector-continuity.mjs` checks the retained alpha.34 records.
`tools/verify-alpha36-vector-continuity.mjs` checks every existing alpha.35 fixture
byte against a frozen SHA-256 inventory, including the alpha.35 writer corpus.
The historical alpha.33 script compares its superseded snapshot and fails on
alpha.35's already-changed import corpus; the same mismatch occurs at the base.
The current continuity gates preserve those bytes without rewriting history.
