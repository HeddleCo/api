# 0.31.0-alpha.37: retained boundary acceptor attachment bug fix

API-only bug fix from alpha.36 (`1154fc6f`). The opaque attachment admission
helper previously always extracted the original party's envelope. A paired
boundary acceptor after an ordinary owner Rotate therefore failed the mandatory
retained-attachment verifier with `Root`, even with independently authenticated
history, accepting authority, signatures and witness testimony.

Rust and TypeScript now share one boundary-writer selector between writer-policy
checks and attachment admission. For basis 2, native P1, import P1 and shared P2
admit the exact attachment in the signed `accepting_author` authority envelope.
The selected evidence must match the complete statement boundary binding and
`signed_acceptance_digest`; exactly one signature must name the signed
`accepting_publisher`. The accepting Spool and authority digest must match too.
Payload verification authenticates the originals, acceptance and receipts before
opaque admission. Original-party attachments and newly forged old-owner
attachments cannot substitute for that admitted attachment. Basis 1 is unchanged,
including delegated import genesis and ordinary retained paired devices.

The alpha.36 review follow-ups in [#360](https://github.com/HeddleCo/api/issues/360)
are included. The redundant full `verify_boundary_acceptance` call is removed
from writer selection; complete boundary verification remains mandatory in the
payload verification path. Portable import carrier validation still requires
separate payload/signature verification before admission. Both selector readers
require integer arrays for the fixed 32-byte publisher and authority digest.
The regression probe showed that `rmp-serde` also accepted binary through its
tuple reader, so Rust now checks the actual MessagePack type explicitly.
UUID and authority-envelope byte fields keep their existing native encoding.

No protobuf layout or older fixture bytes change. The native and import contracts
now state which party's attachment is admitted for each basis. All seven Rust/npm
release version files advance together to `0.31.0-alpha.37`.

5 failed) and 1 in TypeScript (0 passed, 12 failed). The four native/import P1/P2

and 12 TypeScript tests. Negative probes reject a freshly signed old-owner

generator reproduces native P1/P2 byte-for-byte from the REPORT's `.binpb`
fixtures and verifies each generated Rotate with the native history verifier.
