# 0.31.0-alpha.38: typed spool recipients and in-app invitation decisions

Requires merged alpha.37 acceptor-attachment fixes; preserves their authority cuts.

- Replace InvitationRecord's recipient string (tag 3, reserved) with the
  required oneof email=8, handle=9, account_id=10. Hosts privately resolve
  handles once; no response may disclose their resolved account UUID.
- Replace revoked/redeemed (tags 6/7, reserved names) with InvitationState=11:
  pending, accepted, declined, revoked, expired. Migrate stored records before
  serving the new contract. Read additions: created_at=12, updated_at=13,
  inviter=14, inviter_via_agent_label=15, spool_name=16, spool_address=17.
- Add caller-bound SpoolService.AcceptInvitation and DeclineInvitation,
  taking client_operation_id=1, invitation=2 and returning MutationResponse.
  Recheck verified recipient-account auth before state/receipt replay. No link
  secret or prior spool grant. Decline notifies the inviter once, including
  across fresh operation IDs; repeat Accept never recreates a revoked grant.
- Create returns redemption_secret only for email. RedeemInvitation and
  ResolveInvitation become email-only; retain secret/verified matching OAuth
  email redemption. Account/handle invitations use in-app Accept/Decline.
- Add NOT_FOUND / ERROR_REASON_INVITATION_HANDLE_NOT_FOUND=302, field
  invitation.handle. Only public-directory resolvability is disclosed, after
  spool-admin authorization; all unresolvable statuses share one envelope.
- Add spool_invitation (direct ask) and spool_invitation_declined (ambient)
  string kinds, reusing notifications/attention, preferences and outbox.
  NotificationRecord.invitation=10; AttentionItem.invitation=15, kind=16.
  Capabilities ACCEPT_INVITATION=10 and DECLINE_INVITATION=11 advertise actions.
- Notification rules inherit down account → personal/top-level root → child
  spools, nearest matching level first, specificity within each level only.
  Shared system root `spool` is transparent. Bound ancestry at the host's existing
  64/128 nodes and fail closed on incomplete, cyclic or over-bound chains.
- Add EffectiveDelivery.Source.SOURCE_INHERITED=3 and SOURCE_ACCOUNT=4, and
  SpoolRef source_spool=8. Emit the winning ancestor only if readable; otherwise
  keep INHERITED with no identity. Redact unreadable stored selectors too.
  Include descendant effective cells even when they have no local rules.
- Return to inherit by removing all local rules matching a cell. Reject stored
  DELIVERY_UNSPECIFIED; migrate legacy zero rules by explicit removal or DISABLED.
  Security email remains locked. Rust/TS share inheritance, removal, source,
  privacy, enum rejection and 64/128 bound vectors/tests. See
  [notification delivery](../docs/alpha-v2/notifications.md) for exact read rules.
- Member/grant/invitation reads contain humans only. Agents are delegations
  of users and never appear as separate people.

See [administration](../docs/alpha-v2/administration.md) for the state machine,
privacy boundary, inviter fields and transaction requirements. Rust/TypeScript
helpers validate shape, response privacy and decisions. Hosts must integrate
verified auth, serialized storage and delivery; this API PR ships no weft/UI
implementation.
