# 0.31.0-alpha.39

This release follows alpha.38 and combines three contract changes.

- `IdentityService.GetSignupInvitationCode` and
  `SpoolService.GetInvitationCode` read the original pending invitation code
  for its creator. Their request is `invitation: RecordRef`; their response is
  `redemption_secret: bytes`. Ordinary records and observations never carry
  codes. See [invitation-codes](../docs/alpha-v2/invitation-codes.md) for creator
  isolation, expiry/lifecycle, encrypted retention/destruction, audit and limits.
- `IdentityService.SuggestPrincipals` supplies "Add people" rows by literal
  handle/display-name prefix, within current co-members plus at most one exact
  public-handle hit. Requests contain `prefix` and optional `spool`; responses
  contain `principals: SuggestedPrincipal[]` with only `handle`, `display_name`
  and `kind`. There are no agent rows or principal/account IDs. Two-scalar
  minimum, 20-row cap, account rate limiting and uniform non-member scope
  refusal are normative host requirements.
- `ApprovalGroupRecord.member_role` adds live effective-role membership to
  `principal_ids` explicit extras. Inherited roles count. Landing MUST reevaluate
  current membership: a demoted or removed approver stops counting unless still
  an eligible explicit extra. `PutApprovalGroup` and `PutReviewPolicy` reject
  READER thresholds with `APPROVAL_ROLE_BELOW_ELIGIBILITY_FLOOR` (403).

`SpoolEvent.approval_group` changes from `ApprovalGroupRecord` to
`ApprovalGroupView`. This is an intentional alpha read-model cutover: regenerate
bindings and migrate observation consumers. The view reserves field 5 /
`principal_ids`; it supplies `resolved_members` as ID-free people and
`role_member_handles` to distinguish role-selected members from explicit extras.
Write callers continue using `PutApprovalGroupRequest.group: ApprovalGroupRecord`.
Existing stored `ReviewPolicyRecord.minimum_role = READER` evaluates at WRITER
(Developer), while new writes are refused. See the normative
[people and role-group contract](../docs/alpha-v2/people-and-approval-groups.md).

Rust and TypeScript expose validators and pure helpers for these contracts,
with shared JSON vectors and mutation checks that require real failures before
restored passing results. These packages define host obligations; they do not
implement hosted membership queries, rate-limit storage, invitation ciphertext
storage or atomic landing transactions.
