# 0.31.0-alpha.41: provider hosts and email invitation expiry

GITLAB people suggestions accept any canonical lowercase DNS provider host
containing a dot, including `gitlab.example.com:alice`. `gh:` remains
GITHUB-only; bare `gitlab:` and uppercase or malformed hosts are refused.
Rust and TypeScript share the suggestion fixtures.

Email-recipient CreateInvitation now requires a finite, valid `expires_at`.
Omission returns `INVALID_ARGUMENT / ERROR_REASON_FIELD_REQUIRED` with field
`invitation.expires_at`. Hosts enforce future expiry and their configured
`INVITATION_CODE_MAX_LIFETIME_SECS`. Handle/account_id invitations retain
optional expiry. Clients creating email invitations must supply an expiry.

No protobuf changes. Rust/TypeScript portable create validators enforce required
email expiry and timestamp validity; hosts implement clock and lifetime checks.
See [administration](../docs/alpha-v2/administration.md) and
[invitation codes](../docs/alpha-v2/invitation-codes.md).
