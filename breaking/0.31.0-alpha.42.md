# 0.31.0-alpha.42: Fetch carries HYBRID imported ancestry; FetchOpen selects inside an import floor

Fixes HeddleCo/api#378 (found as HeddleCo/weft#2617): a fresh clone of a
HYBRID-imported spool received only the import tip, because nothing on the wire
could carry the converted Git ancestors. A HYBRID import is ONE signed native
operation per branch; its Git ancestors are States in the tip State's parent
closure ("the import floor"), not operations, so `ReplicationOperations` cannot
carry them and a source pack carries only the selected State. The receiver's
visibility walk then treated the missing parent as a private ancestor and
showed only an embargo placeholder.

## Protobuf (additive)

- `FetchServerFrame.import_ancestry = 10` (`ImportAncestryPage`): the converted
  Git ancestors of one delegated import tip, paged, States only (never trees or
  blobs). Each page binds `thread`, `tip`, the exact
  `signed_operation_digest` of the authorizing
  `SignedDelegatedImportOperationV1` in `TransferReady.import_authority`,
  `coverage` (`COVERAGE_FLOOR` complete closure, `COVERAGE_PATH` a parent chain
  to the selected revision), `page_index`/`page_count` and `member_count`.
- `ImportAncestorState { id, canonical_state }`: one State's canonical bytes.
- `FetchOpen.revision` (and so `TransferReady.current`) may name a State inside
  an authenticated import floor. The endpoint proves membership with a
  `COVERAGE_PATH` (or `COVERAGE_FLOOR`) page set and the source pack carries
  exactly that State's tree closure, so a client lazily materializes any older
  imported commit.
- `TransferSelection.exclude_revisions` gains a defined use: an entry naming an
  import tip tells the endpoint the client already holds that tip's complete
  floor, so the endpoint omits its `COVERAGE_FLOOR` page set. A `COVERAGE_PATH`
  set for a selected inside-floor revision is still sent. Endpoints that
  rejected any non-empty `exclude_revisions` must accept these.

Deploy weft before the heddle client: an endpoint built before alpha.42 rejects
non-empty `exclude_revisions`. Weft must also populate `floor_tiers` on every
ancestry page before clients requiring this summary deploy.

`buf breaking` against alpha.41 passes; no field is removed or renumbered.

## Why no new signed floor digest

The floor is already bound by signature. The import operation's
`resulting_content_digest` commits to the exact tip Capture, the tip State
commits to its parent StateIds, and every member commits to its own parents, so
the set is a Merkle closure rooted at the signed tip. A receiver that checks
every State's address, that every carried State is reachable from the tip, and
that every referenced parent down to the signed causal frontier is carried has
verified "exactly that floor". `member_count` and `page_count` are endpoint
bookkeeping for early refusal and truncation detection, never trust; a server
claimed digest would be weaker than the chain it would summarise. Nothing in
`ImportPublicProofBundleV1`, the P3 witness statement or the manifest commits
to a flat floor digest or count, and none is added.

## Receiver checks (normative; see the `ImportAncestryPage` comment)

1. `TransferReady.import_authority` present and independently authenticated;
   `signed_operation_digest` names one of its operations whose resulting
   frontier selects a carried original whose Capture State is `tip`.
2. Pages of one floor repeat identical headers (including `floor_tiers`), may
   arrive in any order, and are contiguous after sorting by `page_index` with
   no gap or repeat; carried States sum to `member_count`.
3. Every State decodes canonically and its content-derived StateId equals
   `id`; duplicates are rejected.
4. Every carried State is reachable from `tip` through carried States (nothing
   outside the floor is accepted).
5. `COVERAGE_FLOOR`: every parent named by the tip or any member is carried or
   is the source State of one of the tip operation's causal parents; a missing
   middle State fails.
6. `COVERAGE_PATH`: `TransferReady.current` is a carried State.
7. Install only after Complete, with the selected revision's closure, and
   record the floor and its tier summary. The local visibility walk stops at
   floor members; the tip's causal parents (its frontier) are still walked.

Every delegated import operation in the carried causal ancestry whose tip has
parents outside the signed frontier MUST be covered by one page set unless the
client excluded that tip; an uncovered floor fails the Fetch.

## Limits

A page carries at most 4096 States and fits `ReadBudget.max_frame_bytes`.
Pages use a separate ancestry budget, charged separately from the 100000-object source pack limit. A
receiver MUST accept at least 131072 States and 256 MiB of ancestry per Fetch
so the largest known HYBRID history (boost, 94794 commits) fits; endpoints
refuse larger imports at Prepare rather than truncating a floor.

## Consumers

- heddle (HeddleCo/heddle#2004): pack validation, thread-api fetch staging,
  install, and a repo visibility walk that stops at the import floor instead of
  at 4096 States.
- weft: `source_fetch.rs` serves floor pages from `native_import_floor_members`,
  resolves inside-floor revisions, and honours `exclude_revisions`.

## Floor tier summary

`ImportAncestryPage.floor_tiers = 9` is a required-present
`ImportFloorTierSummary`, repeated identically on every FLOOR and PATH page.
Weft sends every positive `native_import_floor_tiers` row for the exact
(publication, Thread): Private and Restricted only, grouped by (tier, label),
with `tier_rows` counting all member tier rows across all sources and origins.
Rows are sorted by (tier, label), unique, and positive. An unconstrained floor
has a present empty summary. A PATH summary covers the whole floor, not only
its carried path. Refuse incomplete floors (`incomplete_members != 0` or any
incomplete member node). The receiver persists this current disclosure
constraint with the floor and intersects it with local member sidecars.
The summary does not replace the signed Merkle closure proof or grant access.
