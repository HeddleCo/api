# 0.31.0-alpha.46: incremental import discovery and opt-in pull-request heads

HeddleCo/api#400 raises the complete-discovery work ceiling from 4,096 to
1,048,576 refs. A safety ceiling bounds hostile advertisement CPU work without
requiring retention of the complete advertisement. Pages remain capped at 512
refs and names at 1,024 UTF-8 bytes; signed selections remain capped at 256.

Rust and TypeScript export `DiscoveryValidator`, `DiscoveryDigest`,
`DiscoveryOptions`, `DiscoverySelectionMode`, the complete-list digest adapter,
and Prepare/Commit helpers accepting finished local evidence. The validator
retains a running SHA-256, one previous name, bounded source metadata and at most
256 selected records. Strict global UTF-8 ordering proves
uniqueness. Hosts must authenticate snapshot/cursor continuity and complete
coverage before finish; digest evidence is not a signed record or authorization.

Discovery retains alpha.45 acceptance of ref names and kind hints: length,
ordering, OID and hash-algorithm checks apply to evidence. Strict branch namespace
and shape checks apply only to signed selections. Other namespaces are hashed
under neutral kind 0; discovered refs are pin evidence, never signed content.
False/omitted options preserve alpha.45 ref validation outcomes within its old
bounds. Prepare accepts absent refs as unknown OIDs; Commit preserves frozen
pins after upstream movement or deletion, and still refuses OBSERVE selections
when a current selected OID is known. Metadata-only fixtures remain unchanged.

Source binding adds `Bounds` rejections for clone URLs, provider repository IDs
and installation IDs exceeding 4,096 UTF-8 bytes, or connections whose encoded
`RecordRef` exceeds 4,096 bytes. These bounded metadata checks apply when creating
or checking discovery evidence, independently of page/ref bounds.

`DiscoveryDigest::digest()` / TypeScript `digest` is a standalone SHA-256
identifier committing to source custody/format, discovery options and complete
ordered evidence. Its prefix includes the source binding and option; private
selection and admission-phase bindings additionally guard evidence reuse.
Page partitions do not affect the identifier.

Additive `include_pull_request_refs` (tag 4) on `ProviderRefsRequest` and
`ResolveImportSourceRequest` opts in to `refs/pull/<positive decimal>/head`.
Additive `ProviderRef.Kind.KIND_PULL_REQUEST` (3) labels them. Zero, leading
zeros and merge refs are not classified as pull-request heads; any such records
in complete host evidence use neutral kind 0. Cursors bind the option.
Pull-request heads are source-side discovery evidence only: signed scopes,
manifests and all non-discovery verification reject `refs/pull/...` selections.
There is no native `refs/pull` destination namespace; a later step maps source
pull-request heads to native threads. Existing tags, enum values, signed encodings,
fixture vectors and existing wire bytes do not change. No Buf breaking override
is used.

Shared SHA-1/SHA-256 recipes cover 20,000 refs (8,000 branches, 8,000 pull-request
heads, 4,000 tags), page partitions of 1/127/512 and identical digest expectations
in both languages. Tests also cover page-local failures, cross-page duplicate
names, failed-validator reuse, absent selections, pin movement, opt-in namespace
rules, exact ceiling/overflow and every existing repository fixture against the
former one-pass checks.

Cargo and npm packages move together to `0.31.0-alpha.46`. Tagging and publication
remain separate release steps.
