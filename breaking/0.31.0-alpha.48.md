# 0.31.0-alpha.48 — endpoint support for collaboration and outlines

Closes HeddleCo/api#410. Cargo and npm advance together from alpha.47 to alpha.48.

The additive `MandatoryProtocolFeature` values are stable:
`COLLABORATION_MENTIONS_V1 = 2`, `DISCUSSION_TAGS_V1 = 3`, and
`CONTENT_OUTLINE_V1 = 4`. Hosts advertise implemented support in the sorted,
unique `DescribeEndpointResponse.protocol.mandatory_features` set. No existing
method gains a mandatory feature. Commands without new variants remain usable.

Rust `v2::protocol::{host_supports, require_feature}` and TypeScript
`./v2/protocol`'s `hostSupports` / `requireFeature` check set membership.
Missing support produces `Reject::MissingFeature(feature)` or
`MissingProtocolFeatureError(feature)`. Existing HYBRID checks now accept
additional advertised features while still requiring protocol version 2 and
`IMPORT_AUTHORITY_HOST_WITNESS_V1`.

Rust mention encoders/validators, discussion tag-edit encoding and outline input
validation require a final `Option<&ProtocolCompatibility>` argument. Opening
tags use `canonical_discussion_open_tags`; generic context-tag encoding remains
unchanged. TypeScript collaboration signing/delivery validators and outline
input validation accept an optional final peer argument. Omission fails closed
for new variants, while old commands keep working. Typed clients automatically
gate delivery requests on their negotiated peer. See the
[collaboration contract](../docs/alpha-v2/collaboration-mentions-tags.md) and
[outline contract](../docs/alpha-v2/content-outline.md) for usage and peer lifetime.

No protobuf field, method requirement, golden vector, canonical record,
operation ID or signature changes. Buf breaking against main requires no override.
Tagging, release publication and downstream host advertisement remain separate.
