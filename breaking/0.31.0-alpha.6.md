# 0.31.0-alpha.6 planned hard cut: timeline origin credential identity

This is the intentional pre-1.0 breaking override for
[api#257](https://github.com/HeddleCo/api/issues/257). This branch does not
change package versions or publish a release. Weft currently returns
`UNIMPLEMENTED` for the timeline writes, and Heddle has not shipped a timeline
producer; no alpha.5 timeline wire consumer needs migration. The release owner
coordinates exact consumer pins and the alpha.6 tag.

`buf breaking --against '.git#branch=origin/main,subdir=proto'` reports only
these intended FILE-level breaks, four diagnostics per field:

- `TimelineOriginEndorsement` field 8 changes from implicit-presence `bytes
  origin_credential_id` to explicit-presence message `credential_identity`.
  This changes cardinality, JSON name, type, and field name.
- `TimelineAcceptanceScope` field 2 makes the same change. This changes
  cardinality, JSON name, type, and field name.

The new message has an exact `server_issued` or `offline_derived` oneof. The
origin transcript changes from `heddle-timeline-run-origin-v1` to `-v3` and
includes the variant tag and its exact IDs. The offline identity additionally
commits to the entire ordered chain with a domain-separated SHA-256 digest of
all raw revocation IDs from issued ancestor to terminal. It requires uninterrupted
signature-v1 chaining and rejects any v0 block. A fresh acceptance cannot omit
the chain unless an exact verified pre-expiry registration already stores the
cryptographic binding and original public key. The owner timeline acceptance
capability changes from format 2 / `heddle-owner-capability-v2` to format 3 /
`heddle-owner-capability-v3`; format 2 is rejected. V1 PURGE capability bytes
and signatures are unchanged. The registration and upload digest layouts still
include the origin digest, which now binds the new transcript. The acceptance
transcript layout remains v1 because its signed fields and encoding are
unchanged; its origin digest and exact format-3 owner bundle carry the new
identity. No legacy-origin fallback is allowed.
