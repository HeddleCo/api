# 0.6.0 SearchService streaming cutover

This release is a coordinated pre-1.0 contract correction for the Search API.

- `SearchService/Search` changes from unary
  `rpc Search(SearchRequest) returns (SearchResponse)` to server-streaming
  `rpc Search(SearchRequest) returns (stream SearchEvent)`.
- `SearchResponse` is removed. Stream frames are `SearchEvent` with a oneof of
  `MatchBatch`, `Progress`, `Facets`, `Alert`, and terminal `Done`.
- `SearchRequest` gains `kinds` (tag 5), `filters` / `ScopeFilters` (tag 6), and
  `union_rank` (tag 7). Existing tags 1–4 are preserved.
- `SearchEntityKind` fills reserved values 6–10 (`STATE`, `SYMBOL`, `CONTENT`,
  `MESSAGE`, `ANNOTATION`).
- `SearchHit` keeps Tier-1 oneof tags 4–8 and adds common fields
  `matched` (9) / `change_id` (10) plus Tier-2 arms 20–24
  (`StateHit`, `SymbolHit`, `ContentHit`, `MessageHit`, `AnnotationHit`).
- New supporting types: `TimeRange`, `SearchFlags` (optional-bool tri-state),
  `MatchKind`, `MatchProvenance`, `SourceStatus`.

## Why no compatibility shim

Search is **unwired** in Weft with **no production consumers** (expected
undispatched SHIPPED/WEFT registration). Unary → server-streaming does not break
live traffic. A dual unary+stream RPC would permanently freeze an obsolete
shape; prefer a single stream RPC and a minor version bump.

`buf breaking` against the previous published descriptor **will fail** on the
method signature and removed `SearchResponse` message. That is expected and
acceptable for this pre-1.0 cutover; document the override in release review
rather than adding a shim.

## Consumer adoption

1. Publish `heddle-api` / `@heddleco/api` **0.6.0** (this package).
2. Weft implements the streaming Tier-1 handler (unified-search P1b).
3. Clients repin to 0.6.0 and consume `stream SearchEvent` (always await `Done`).

No dual-registration or legacy unary alias is provided.
