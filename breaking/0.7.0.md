# 0.7.0 spool state-visibility rename

This launch release makes the spool-level state-visibility baseline a
first-class create-time contract setting instead of retaining the orphaned
`default_` name.

- `SpoolSettings.default_state_visibility` is renamed to
  `SpoolSettings.state_visibility`. Protobuf tag 2 and the
  `SpoolStateVisibility` type are unchanged, so the encoded wire value remains
  stable; generated Rust and TypeScript field names change.
- `CreateSpoolRequest.settings` is added at tag 7 so create callers can send the
  complete `SpoolSettings`, including `state_visibility`.
- `IdentityService.ClaimNextDropCode` and `RemainingDropCodes` are additive
  hosted-Iroh methods for public invite drops.

## Why no compatibility shim

All pre-1.0 consumers exact-pin the package and move in lockstep. Keeping a
second `default_state_visibility` field or generated alias would create two
names for one baseline and allow them to diverge. Consumers must repin to 0.7.0
and use `state_visibility`; the retired field name is reserved and cannot be
reused.
