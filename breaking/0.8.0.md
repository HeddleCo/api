# 0.8.0 unified Visibility enum

This breaking revision replaces the two differently-numbered visibility
enums with one shared type. Field names and tags are unchanged; the
**enum type** and **numeric assignments** change.

- `SpoolVisibility` `{UNSPECIFIED=0, PRIVATE=1, PUBLIC=2}` and
  `SpoolStateVisibility` `{UNSPECIFIED=0, PUBLIC=1, INTERNAL=2, PRIVATE=3}`
  are removed. Their type names are retired and must not be reused.
- Every field that used either enum now uses `Visibility`:
  - `SpoolSettings.visibility` (tag 1)
  - `SpoolSettings.state_visibility` (tag 2)
  - `SetNamespaceVisibilityRequest.visibility` (tag 2)
  - `CreateSpoolRequest.visibility` (tag 5)
  - `HostedNamespace.visibility` (tag 8)
  - `SetSpoolVisibilityRequest.visibility` (tag 2)
  - `ImportOperationSpec.requested_visibility` (tag 4)
- Canonical numbering is restrictiveness order:

  ```
  VISIBILITY_UNSPECIFIED = 0
  VISIBILITY_PRIVATE     = 1
  VISIBILITY_INTERNAL    = 2
  VISIBILITY_PUBLIC      = 3
  ```

  There is no numbering that preserves both retired enums at once. The
  old collision (`SpoolStateVisibility.PUBLIC = 1 = SpoolVisibility.PRIVATE`)
  is gone: wire value `1` means PRIVATE on both fields.

## Why no compatibility shim

A numeric cast between the retired enums published private history as
public. Keeping both types — or a dual-numbering alias — would leave
that footgun in the generated API. All pre-1.0 consumers exact-pin and
move in lockstep (weft compiles against this proto in the same change).
Map by variant **name**, never by discriminant.

`buf breaking` against the previous published descriptor **will fail**
on the deleted enums and the changed field types. That is expected for
this pre-1.0 cutover; document the override in release review rather
than adding a shim.

## Consumer adoption

1. Orchestrator publishes `heddle-api` / `@heddleco/api` **0.8.0**.
2. Weft maps `Visibility` by variant name through the stored string
   token (`private` / `internal` / `public`). Stored rows are
   name-based; this is a wire break, not a data remapping.
3. Clients repin to 0.8.0 and send/read `Visibility`. Do not interpret
   a 0.7.0 discriminant under the 0.8.0 numbering (old state
   `PRIVATE=3` is now `PUBLIC=3`).
